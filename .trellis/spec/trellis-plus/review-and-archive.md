# Review and Task Archive

## Submit-ready review

After implementation and applicable checks, but before staging, committing, completing, or archiving, compare the task acceptance, diff, actual checks, and remaining risks. Record one of `human-required`, `human-optional`, or `human-not-needed`. Reuse authorization and decisions already supplied by the user.

`human-required` blocks commit or archive when a material check could not run, required mobile or device behavior remains unverified, product or visual judgment is unresolved, or the change affects authentication, permissions, security, billing, data migration/deletion, deployment, CI/CD, or irreversible behavior. First perform checks that the agent can safely run. Ask only for the specific remaining signal: changed behavior, checks and outcomes, exact scenario, desired pass/fail or diagnostic feedback, and the decision affected. `human-optional` is nonblocking for a low-risk residual preference or useful smoke test after relevant checks pass. `human-not-needed` applies when a specific reason shows manual review adds no meaningful signal, such as a focused, validated documentation-only change. For bootstrap, assess current development-readiness acceptance rather than requiring unrelated future product implementation.

## Attribution and supported archive route

For a task completed with Codex participation, use exactly one task-level attribution trailer on its archive commit: `Co-authored-by: OpenAI Codex <codex@openai.com>`. Ordinary work or journal commits do not receive this trailer solely under this rule. Do not attribute unrelated historical work, rewrite Git identity, amend old commits, or create an empty attribution commit.

In Trellis 0.6.17, `python3 .trellis/scripts/task.py archive <task> --no-commit` moves the task to `.trellis/tasks/archive/<YYYY-MM>/`, marks it completed, and clears session pointers while skipping Trellis's built-in automatic commit. It may also update child records and still runs any configured `after_archive` hooks; inspect those hooks before executing it. Without `--no-commit`, the normal command stages task bookkeeping and automatically commits a fixed message when `session_auto_commit` is enabled (the current default); it has no trailer interface. Before using the no-commit route, inspect task/archive state, branch metadata, child records, exact candidate paths, the review gate, and Git status. Use `--skip-branch-validation` only if the installed command requires it for a genuinely non-PR-backed task; do not disguise invalid PR metadata.

After a successful move, update project-owned task references and mainline, inspect `git status --short` and `git diff --check`, and stage only the explicitly reviewed old/new task paths and other authorized project-owned changes. Never force-add or broadly stage local assistant settings, secrets, backups, unrelated work, or protected Trellis customizations. With separate commit authorization, create the archive commit with a task completion summary, actual checks/limitations, and the trailer, then inspect `git show --format=full --name-status HEAD` and confirm exactly one trailer.

The separate journal interface is `python3 .trellis/scripts/add_session.py --title <title> --commit <oid-or-dash> --summary <summary> --no-commit`. Without `--no-commit`, the current default can stage and commit the developer's journal/index and current task paths. Check the installed help and actual candidate paths before using it; journal-only commits do not repeat the task attribution trailer.

If the move succeeded but the commit failed or remains unauthorized, verify the archived path and history, then resume only the pending commit when authorized; do not archive a second time. If provenance, a supported message route, status, or the prior commit is uncertain, report the gap instead of silently rewriting runtime or history. A pending required archive commit means initialization delivery is incomplete.
