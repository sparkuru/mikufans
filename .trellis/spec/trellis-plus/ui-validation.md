# UI Planning and Validation

The current settings interface is native Android Views (`app/src/main/java/im/majo/mikufans/SettingsActivity.kt` and `SettingsContentFactory.kt`). It is not a browser application. Web Playwright cannot validate native view interactions or LSPosed hooks; use the device workflow in [development.md](development.md).

## UI/UX Pro Max integration

For a task changing visible UI structure, interaction, accessibility, or visual design, plan with the project-local UI/UX Pro Max skill before implementation when it is initialized. On Codex its entry is `.codex/skills/ui-ux-pro-max/SKILL.md`, with `scripts/search.py` and `data/` beside it; these are local assistant files, not tracked project policy. If absent on a new machine, reuse applicable initialization authorization or ask once before running `uipro init --ai codex`; do not overwrite an existing installation. If the user declines, record the decision in the existing task and continue normal UI planning and validation without UUPM. Verify an accepted installation's entry and `python3 .codex/skills/ui-ux-pro-max/scripts/search.py --help`. The CLI installed for the initial setup was 2.10.2; another machine must install and initialize its own compatible local integration.

A newly installed skill may require a new Codex session before it appears in the session's skill catalog. The local search script can be checked separately; its success does not prove automatic skill discovery on another machine.

During planning, read that local skill, search for a task-specific design system with `python3 .codex/skills/ui-ux-pro-max/scripts/search.py "<Android Views task and visual direction>" --design-system -p "Mikufans <task>" -f markdown`, and record selected decisions, relevant states, accessibility and device expectations in the task's `design.md`. The installed CLI offers `jetpack-compose` but no Android Views stack; do not falsely label this View-based UI as Compose. Where its source and license permit, retain raw generated research under the active task's `research/` directory; otherwise retain an original decision summary and references. No design is approved merely because a search produced it.

Register the approved design, applicable research, this file, and relevant shared policy individually in both task context manifests. Implementation follows the approved design and records material changes; checking compares actual interaction and states against acceptance, including readable text, touch targets, labels, focus, color contrast, system navigation, available size/orientation, loading/error/disabled/success states, and motion where relevant. Promote stable, approved project-wide decisions here only after verification; keep task-specific design in the task.

## Native and browser coverage

For native changes, use the available authorized device or a suitable emulator, document Android and host versions, test the changed action and resulting state, and capture sanitized diagnostics where useful. Exercise small-screen or landscape behavior when the affected screen requires it; device evidence is distinct from an APK build. Ask for a targeted human assessment only for subjective design, assistive technology, hardware, private environment, or other behavior that cannot be verified by the agent.

If a future task adds a browser-accessible UI, classify each changed path as Playwright-required, covered by an existing equivalent runner, not effective, or unavailable. For an automatable path, add or reuse the smallest repeatable test and verify the relevant desktop and narrow-mobile flows, states, and accessible names; record exact commands, fixtures, viewports, and artifacts. Before its first submit-ready gate, that task must establish a single shared browser-validation profile here with the actual execution mode, dependency/browser setup, startup/readiness and base URL, focused and CI commands, browser projects, fixtures, accessibility and visual-baseline policy, and failure artifacts. Do not invent those values now. Record unavailable prerequisites rather than calling the check passed.
