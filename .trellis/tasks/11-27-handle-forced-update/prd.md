# 处理更新检测与强制更新

## 目标与背景

完成 [README](../../../readme.md) 中“去更新检测，适配下发强制更新行为”的需求，使 Bilibili 国际版 `com.bilibili.app.in` 3.20.4 的用户能够继续使用旧版，免受应用内更新检查及强制更新提示的阻断。

Android 11 开发板上的未修改宿主可以进入首页，首次启动没有复现强制更新；“我的 → 设置 → 关于哔哩哔哩”的手动检查当次提示当前已是最新版本。后续定位的更新路径、实际测试条件、尚未覆盖的触发条件和截图见 [调查记录](./research/update-investigation.md)。

## 需求

- 拦截目标宿主的应用内自动更新检查、用户手动更新检查及强制更新提示；手动检查被拦截时不得错误地声称已经查询到最新版本。
- 提供更新拦截开关，默认开启，并允许用户关闭；关闭后恢复宿主原有的更新检查和提示行为。
- 开关与已有设置保持一致，跨进程和重启后正确保存；如果更改需重启宿主，应在界面明确说明。
- 保持正常启动、登录、内容访问和其他已有设置的行为，不误拦截无关响应。服务端若拒绝旧版请求，应如实记录，不能将提示消失当作服务恢复。

## 验收条件

- [ ] 未保存过该项设置时，界面和宿主读取的开关均默认为开启；关闭、重启和重新开启后，界面与宿主读取状态一致。
- [x] 开启时，目标版本的自动检查和“关于哔哩哔哩”中的手动检查被实际拦截，手动操作不误报查询成功；通过日志、受控输入或其他可审查证据验证，而非只观察弹窗消失。
- [x] 对可复现或可控的强制更新样例，开启时更新提示不阻断操作；关闭开关并按实现要求重启宿主后，自动、手动检查和该样例的提示恢复原有行为。
- [x] 在可用设备上检查开关的可读性、可操作性、无障碍名称和必要的重启说明，并验证目标宿主的启动及受影响的基本内容访问；记录环境、触发条件和不可验证项。
- [x] 找不到目标方法或无法验证时明确记录结果，不影响宿主正常启动，也不将未安装的 hook 报告为成功。

## 范围外

- 修改 Android 系统或应用商店的更新机制、其他应用的更新行为，或服务端拒绝旧版客户端的策略。
- 宣称支持未经验证的其他宿主包名或版本，也不对其引入未经验证的行为变更。
